# 摹影 Moying

一个会自己过日子的角色扮演引擎。她有自己的作息、工作、朋友和情绪；你不找她的时候，她的生活照样往前走——而且**走过的事不会自相矛盾**。

不是聊天机器人套一层人设皮，而是把「故事」当成一条必须自洽的时间线来跑：她在哪、和谁在一起、几点说过什么，都是可校验的结构化事实，不是模型随口编的散文。

---

## 它解决了什么问题

很多角色扮演系统跑久了会出现这几类硬伤，摹影从架构上避免了它们：

| 常见硬伤 | 摹影的做法 |
|---|---|
| 同一天下午「出了两次门」 | 散文不是真相。状态由结构化的 `move/act` 事件派生，位移前后矛盾会被程序直接拦下 |
| 说给虚构角色的话发给了真实用户 | 收件人是一等实体。虚构角色**没有投递地址**，物理上发不出去 |
| 说着说着就带句号、越来越热络 | 句尾句号由代码强制删除；说话长度按关系阶段分档，字数由程序截断 |
| 「你怎么醒这么早」说过又说 | 她说过的话进时间轴，下一轮做归一化去重，重复就打回重写 |
| 凌晨两点演化出「该起床了」 | 睡眠时段窗口 + 叙述时钟校验，写错时刻直接判为硬矛盾 |
| 关系永远停在初始设定 | 相处方式由**世界模型按剧情演化**，不是写死的模板 |

## 核心机制

### 1. 世界状态优先于散文

一个回合分两阶段，各自用不同的模型：

```
阶段一（story 路由）→ 判定世界里发生了什么：她在哪、在做什么、谁在场
                      ↓ 程序校验 R1~R9，矛盾就带违规点回灌重写
阶段二（chat 路由）→ 基于「已确认无矛盾」的状态说话，产出对白
                      ↓ 出站守卫 + 文体强制 + 字数限流
```

校验规则：

| 规则 | 内容 |
|---|---|
| R1 时钟单调 | 不得倒流，也不得超前于现在 |
| R2 地点占用 | `move` 的出发地必须等于那一刻的实际所在地 |
| R3 在场一致 | 角色只能出现在他被允许的地点，否则标 `remote` |
| R4 作息窗口 | 凌晨不该在公司、工作日白天不该在家 |
| R5 跨度重叠 | 同一时段不能有两个进行中的持续事件 |
| R6 引用存在 | 提到的角色必须已注册 |
| R7 叙述时钟 | 散文里写的「现在几点」必须与事件时刻一致 |
| R8 睡眠时段 | 睡着时不写起床、洗漱、上班这类清醒活动 |
| R9 叙事篇幅 | 散文太短（流水账）会被打回重写 |

### 2. 消息归属三重保障

`Actor` 分四类：`self`（她）/ `real_user`（真实用户）/ `real_group` / `fictional`（虚构角色）。

- **类型层**：虚构角色 `deliverable = false`，且不可篡改
- **地址层**：`resolveEndpoint()` 对虚构角色返回 `null`——没有投递路径
- **守卫层**：出站必须带 `addresseeId`，缺字段或发给虚构角色的一律丢弃并记账

### 3. 主动联系（她会先找你）

与「回复意愿」是两条独立的路：

- **回复意愿**：你发了消息，她想不想回（分数累积 + 半衰期衰减 + 回复成本 + 作息调制）
- **主动动机**：没人找她，她自己想不想找你（关系阶段基准 × 忙闲 × 时段 ± 新鲜事/久未联系），睡着时为 0

两条都受睡眠与日程约束：**周末在家不算忙**，只有工作日班段内或真的在公司/路上才算。

### 4. 关系会演化（不是写死的模板）

你只填两样：**关系类型**和**初始相处方式**。之后每当关系进一档，世界模型结合「角色卡 + 关系来历 + 这一档的定义 + 最近真的发生过什么」，把上一档的相处方式**改写**成这一档合适的样子——明确要求淘汰掉与新阶段矛盾的条款。

所以它能扮的不止是恋人：朋友、故去的亲人、同事、某个故事里的角色，填 `kind` 和 `initialMode` 就够了。

五档亲疏：陌生 → 疏离 → 熟悉 → 信任 → 依赖，每档自带说话长度上限、可解锁的口头禅层级、允许/禁止的表达，以及要解除的角色卡红线关键词。

### 5. 文体由代码强制

「句尾不用句号」不是靠提示词求模型，而是 `enforceStyle()` 直接删。说话长度按阶段截断（疏离期：单条 ≤6 字、一轮 ≤2 条、总 ≤12 字）。口头禅按关系分层解锁，没到那份上的会明确列为「现在不要用」。

## 目录结构

```
src/
  onebot/     OneBot v11 收发、表情目录、出站队列（含守卫与限流）
  world/      时间、状态机、校验规则、时间轴视图、演化游标、事件播种器
  persona/    角色卡、印象、关系、关系演化
  narrator/   世界阶段、对话阶段、回合编排
  turn/       回复意愿、主动动机、消息合并缓冲、字数限流
  style/      文体强制
  features/   表情包（导入 / 识图标注 / 对话使用）
  export/     故事导出（Markdown / JSON）
  api/        Web 控制台后端
deploy.sh     一键部署（装 Docker / 生成密钥 / 拉起全栈 / 回填 token）
docker-compose.yml  全栈编排：协议端 + 引擎
templates/    标准格式模板（新装从这里起步）
scripts/      init-data.js 初始化、migrate-actors.js 数据迁移
data/         运行时配置与数据（不进版本库）
```

## 部署（一键）

只需要两样东西：一台装了 Linux 的服务器，和一个小号 QQ。

```bash
git clone <你的仓库> moying && cd moying
bash deploy.sh              # 交互式：只问控制台令牌和 noVNC 密码
# 或
bash deploy.sh -y           # 全默认，随机生成这两个凭据
```

脚本会自动做完这些事：

1. 检测并安装 Docker Engine 与 Compose v2（已有则跳过）
2. 生成 `.env`（权限 600）：端口、绑定地址、镜像、凭据
3. 从 `templates/` 生成 `data/` 下的五份配置，并写入控制台端口与令牌
4. 构建镜像、拉起协议端（SnowLuma + noVNC）与摹影引擎
5. 等协议端生成 OneBot token，**自动回填**到 `data/config.json` 并重启引擎
6. 健康检查通过后打印控制台地址、令牌、noVNC 地址与密码

部署完还有三步：

1. 打开 noVNC 地址，用手机 QQ 扫码登录机器人账号
2. 打开控制台 →「API 配置」页，填 chat / story / vision 三套模型的 `baseUrl`、`apiKey`、`model`，点「测试连接」
3. 到「角色卡 / 其他角色 / 用户与关系 / 世界」填设定（`templates/` 下有标准格式模板）

### 常用命令

```bash
docker compose logs -f moying                      # 看引擎日志
docker compose --env-file .env up -d --build       # 更新代码后重新构建
bash deploy.sh                                     # 重跑，保留已有配置与凭据
```

### 可选参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--console-token TOKEN` | 随机 | 控制台登录令牌 |
| `--vnc-password PASS` | 随机 | noVNC 密码（扫码登录 QQ 时用） |
| `--console-port PORT` | 3210 | 控制台端口 |
| `--novnc-port PORT` | 6081 | noVNC 端口 |
| `--webui-port PORT` | 5099 | 协议端 WebUI（只绑 127.0.0.1） |
| `--console-bind IP` | 0.0.0.0 | 只本机访问控制台就填 `127.0.0.1` |
| `--snowluma-image IMAGE` | DaoCloud 镜像站 | 海外可设 `motricseven7/snowluma:v1.14.22` |
| `--no-install-docker` | — | 缺 Docker 时报错退出，不自动装 |
| `-y, --yes` | — | 非交互式 |

### 需要开放的端口

| 端口 | 服务 | 要不要放行 | 说明 |
|---|---|---|---|
| **3210** | 摹影控制台 | **要**（或用 SSH 隧道） | 令牌登录；不想暴露就把 `--console-bind` 设为 `127.0.0.1`，改用 `ssh -L 3210:127.0.0.1:3210 user@ip` 访问 |
| **6081** | noVNC（QQ 扫码登录） | **要** | 受 VNC 密码保护；登录成功后也可以关掉 |
| 5099 | SnowLuma WebUI | 建议**不要** | 默认只绑 `127.0.0.1`，需要时走 SSH 隧道 |
| 3000 / 3001 | OneBot HTTP / WebSocket | **绝对不要** | 只在容器网络内给摹影调用，脚本不发布到宿主机 |

云服务器除了系统防火墙（ufw / firewalld），还要在厂商的**安全组**里放行对应端口。

### 手动部署（不跑脚本）

```bash
cp templates/*.template.json data/ 2>/dev/null || (mkdir -p data && node scripts/init-data.js)
cp templates/config.example.json data/config.json   # 然后手工填 token 与 OneBot 地址
docker compose --env-file .env up -d --build
```

## 开发

```bash
node scripts/init-data.js   # 可选：先生成 data/（正式跑之前用；测试不依赖它）
npm test                    # 140 个测试：时间边界、消息归属、文体强制、关系演化、备份恢复…
npm start                   # = node src/main.js
```

测试用临时目录，不会污染真实数据。刚 clone 的仓库没有 `data/`（含个人信息，不进版本库），
测试会自动从 `test/fixtures/` 补一份通用演示种子；`data/` 里已有文件时一律沿用、绝不覆盖。

> `npm test` 写作 `node --test test/*.test.js`：Node 21+ 会自己展开 glob，Windows 的
> cmd/PowerShell 不展开也没关系。别改成 `node --test test/`——目录参数在部分 Node 22
> 小版本上不被支持，会直接报 MODULE_NOT_FOUND。

## 常见问题

**她不回我消息？** 正常的。回复意愿受忙闲、作息、冷却影响。控制台「投递账本」里标着「她没回」的，是她这回不想回（真人就是这样：忙、困、没看到），不是发送失败——真正发不出去的会标「已拦下 / 给虚构角色 / 限流放弃」。

**故事多久演化一次？** 默认 12±3 分钟，控制台「世界」页可调（0 关闭）。睡着时照常演化，但只写翻身、半醒这类细微的事，不会写出「该起床了」。

**导出故事？** 控制台「故事导出」页选起止时间，导出 Markdown（给人读）或 JSON（给程序读）。

**要迁服务器？** 老机器「备份与恢复」页打包下载 → 新机器同页上传 → 点恢复。恢复前会自动给当前数据打一个安全包，恢复完热重载，不用重启容器。

**控制台显示的「当前」阶段和另一个页面不一致？** 不会了——一键切换与自动演进都会同步写回关系配置。若你手工改过 `data/relationship.json`，重跑一次切换即可对齐。
